Làm chủ Promise.allSettled() và Xử lý Thất bại An toàn trong Ứng dụng Thực tế

Giải quyết triệt để vấn đề "một con sâu làm rầu nồi canh" khi xử lý nhiều API cùng lúc. Tìm hiểu sự khác biệt cơ bản giữa cơ chế fail-fast của Promise.all() và cơ chế bảo toàn của Promise.allSettled().

1. Vấn nạn Fail-Fast của Promise.all()

Trong các hệ thống phân tán và dashboard hiện đại, trang người dùng cần tổng hợp dữ liệu từ nhiều dịch vụ độc lập: Thông tin học viên, Lịch sử nạp xu, Huy hiệu hoàn thành và Khuyến mãi cá nhân hóa. Nếu bạn sử dụng Promise.all(), chỉ cần microservice khuyến mãi gặp sự cố phản hồi (500 Internal Server Error), toàn bộ màn hình sẽ bị sập vào khối catch, khiến học viên không thể xem được cả thông tin quan trọng cá nhân.

cancel Promise.all() Nguy cơ cao

Ngay khi 1 promise bị reject, nó lập tức từ chối toàn bộ danh sách. Không chờ các promise còn lại hoàn tất.

[✓ Success, ✕ Reject(Crash!), … Bỏ qua]
check_circle Promise.allSettled() Chuẩn Enterprise

Luôn chờ tất cả các tác vụ kết thúc (thành công hay thất bại) và trả về mảng báo cáo chi tiết kèm trạng thái.

[{status: 'fulfilled'}, {status: 'rejected'}]

2. Cú pháp & Phân tích cấu trúc Status

demoAsync.js
JavaScript ES2020+ 
// 1. Khởi tạo danh sách các tác vụ bất đồng bộ
const fetchProfile = Promise.resolve({ id: 89, name: "Anh Khoa" });
const fetchNotifications = Promise.reject("Service Unavailable (503)");
const fetchGardenBadges = Promise.resolve(["Mầm tri thức", "Chuỗi 7 ngày"]);

async function loadStudentDashboard() {
  const results = await Promise.allSettled([
    fetchProfile,
    fetchNotifications,
    fetchGardenBadges
  ]);

  results.forEach((result, index) => {
    if (result.status === 'fulfilled') {
      console.log(`Tác vụ ${index} thành công:`, result.value);
    } else {
      console.warn(`Tác vụ ${index} thất bại:`, result.reason);
    }
  });
}

Lưu ý Memory & Timeout: Mặc dù allSettled() không fail-fast, nó vẫn phải đợi Promise có thời gian phản hồi lâu nhất hoàn thành. Hãy luôn bọc các request mạng của bạn với AbortController hoặc cơ chế timeout 5-8 giây để tránh tình trạng "treo mầm xanh" làm chậm toàn bộ giao diện học tập.

Nên dùng Promise.allSettled() thay hoàn toàn cho Promise.all() không ạ?

Mentor PLT: Không bạn nhé. Nếu các tác vụ phụ thuộc mật thiết (ví dụ: Tạo đơn hàng và Trừ tiền), 1 cái lỗi thì phải ngắt ngay để rollback, khi đó bắt buộc dùng Promise.all().

Mentor PLT: Cần Polyfill của core-js nhé em, tính năng này có từ ES2020.
